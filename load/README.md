# Нагрузочное испытание k6

Сценарий находится в `helpdesk.js`. Он использует открытую модель нагрузки `constant-arrival-rate`, выполняет вход один раз в `setup()` и поддерживает два профиля: `mixed` для операций по весам предметной области и `heavy` только для тяжёлой операции `GET /summary`. Порог записан в сценарии: p95 бизнес-запросов меньше 500 мс, доля неожиданных ответов меньше 1 %. HTTP 409 от бизнес-правил считается ожидаемым отказом.

Установите k6 и из корня проекта запустите Docker-стенд с рабочим наполнением:

```sh
just benchmark-up
just benchmark-seed work
```

Перед запуском задайте в окружении `DEMO_PASSWORD` с паролем учебных учётных записей. Одна 30-секундная ступень с одновременным сбором CPU, памяти и соединений PostgreSQL:

```sh
just load-step mixed 2 ../helpdesk-load-results
just load-step heavy 1 ../helpdesk-load-results
```

Частота, длительность и пути настраиваются также переменными `RATE`, `DURATION`, `SCENARIO`, `BASE_URL` и `SUMMARY_PATH` при прямом вызове `k6 run load/helpdesk.js`. Перед отдельной серией заново выполните `just benchmark-seed work`. В каталоге результата для каждой ступени создаются JSON-сводка k6, журнал и CSV с рядом ресурсов через 1 с.
